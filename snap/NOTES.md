# Signward Snap: API notes

Sources (read at build time of this package):
- Transaction insights: https://docs.metamask.io/snaps/features/transaction-insights/
- Signature insights: https://docs.metamask.io/snaps/features/signature-insights/
- Permissions: https://docs.metamask.io/snaps/how-to/request-permissions/ and https://docs.metamask.io/snaps/reference/permissions/
- Allowlisting: https://docs.metamask.io/snaps/how-to/get-allowlisted (insight endowments are open, but endowment:network-access is protected, so allowlisting is needed)
- Snaps API (snap_manageState): https://docs.metamask.io/snaps/reference/snaps-api/

## Handlers
- `onTransaction({ transaction, chainId, transactionOrigin })`. `transaction` is the raw unsigned tx (from, to, data, value, ...), `chainId` is CAIP-2 ("eip155:1"), `transactionOrigin` is only delivered when the manifest sets `allowTransactionOrigin: true`.
- `onSignature({ signature, signatureOrigin })`. `signature` is `{ from, data, signatureMethod }`; `data` is a string for `personal_sign`/`eth_sign`, an object for the typed-data methods. Use `signatureMethod` as the truth. Origin needs `allowSignatureOrigin: true`. Returning `null` means no insight.
- Both return `{ content, severity? }`. Content uses the JSX components (Box, Heading, Text, Row, Address, Divider).

## Severity
- Only `critical` exists (`SeverityLevel.Critical`). For transactions MetaMask shows a warning modal the user must get past before confirming; for signatures the UI appears in a modal after the user presses Sign.
- The transaction docs mark `severity` as experimental/Flask-first. On a build where it is unsupported the content still renders as the normal insight panel, so the plain-English reasons are always visible.

## Behaviour implemented
Critical when any of: origin on community `domains`/`auto` (and not on `allow`); spender, operator, recipient, called contract or EIP-7702 delegate in a non-expired addrs.json entry; unlimited ERC-20 approve/increaseAllowance, setApprovalForAll, Permit or Permit2 grant to a spender not in `src/known.ts`; EIP-7702 delegation. Otherwise a calm panel. No feed data means calm panel only (fail open).

## Reuse of the extension code
`src/verdict.ts` imports `analyze`, `counterpartyOf`, `genericFinding` from `../../src/lib/decode.ts` and `registrableOf` from `../../src/lib/registrable.ts` (both pure). decode.ts imports `./i18n` (chrome.i18n); `snap.config.ts` aliases that one module to `src/i18n-shim.ts`, which serves the English strings in `src/messages.gen.json` (generated by `scripts/gen-messages.mjs` from `public/_locales/en/messages.json`). Rebuilding picks up decoder changes automatically.

## Limits of v0.1.0
- `known.ts` is address-only, not per chain.
- No token symbol/decimals lookup (no RPC); the panel shows contract addresses.
- addrs.json `exp` is read as unix seconds (or ms if above 1e12); `chain` as a chain id or CAIP-2 string, ignored when absent.
